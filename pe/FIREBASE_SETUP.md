# 체육 일지 로그인·동기화 연결

이 설정은 사이트 운영자가 한 번만 합니다. 다른 선생님들은 같은 사이트에서 자신의 Google 계정으로 로그인하면 됩니다.

## 1. 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com/)에 Google 계정으로 로그인합니다.
2. **프로젝트 만들기**를 누르고 이름을 `체육일지`로 입력합니다.
3. Google Analytics는 사용하지 않아도 됩니다.
4. 프로젝트가 만들어지면 **프로젝트 개요 → 웹 앱 추가 (`</>`)**를 선택합니다.
5. 앱 이름을 `체육일지 웹`으로 정합니다. 사이트는 GitHub Pages를 계속 쓰므로 Firebase Hosting은 설정하지 않습니다.
6. 표시되는 `firebaseConfig` 객체를 복사합니다. 나중에도 **프로젝트 설정 → 일반 → 내 앱 → SDK 설정 및 구성**에서 찾을 수 있습니다.

## 2. Google 로그인 켜기

1. **빌드 → Authentication → 시작하기**를 누릅니다.
2. **로그인 방법 → Google → 사용 설정**을 켭니다.
3. 프로젝트 지원 이메일을 선택하고 저장합니다.
4. **Authentication → 설정 → 승인된 도메인**에 `echoeun-glitch.github.io`를 추가합니다. `https://`와 `/Calendar/pe/`는 넣지 않습니다.

## 3. 온라인 저장소와 접근 권한

1. **빌드 → Firestore Database → 데이터베이스 만들기**를 누릅니다.
2. 기본 데이터베이스 `(default)`를 만듭니다. 에디션 선택이 나오면 **Standard**를 선택합니다.
3. 위치는 서울 `asia-northeast3`를 선택할 수 있습니다. 데이터베이스 위치는 만든 뒤 바꿀 수 없으므로 생성 전에 확인합니다.
4. **프로덕션 모드**로 시작합니다.
5. **규칙** 탭에서 이 폴더의 `firestore.rules` 내용을 전체 붙여넣고 **게시**합니다.

규칙은 로그인한 사용자가 `peJournals/자신의 사용자 ID` 문서만 읽고 수정하도록 제한합니다. 로그인하지 않은 사용자, 다른 계정의 문서 접근, 전체 목록 조회는 허용하지 않습니다. 기존 프로젝트에 다른 앱의 규칙이 있으면 전체를 교체하지 말고 해당 경로만 병합해야 합니다.

## 4. 사이트 설정 넣기

`firebase-config.js`의 내용을 다음 형태로 바꿉니다. 값은 자신의 웹 앱에 표시된 것을 그대로 사용합니다.

```js
window.PE_FIREBASE_CONFIG = {
  apiKey: "웹 앱의 apiKey",
  authDomain: "프로젝트ID.firebaseapp.com",
  projectId: "프로젝트ID",
  storageBucket: "웹 앱의 storageBucket",
  messagingSenderId: "웹 앱의 messagingSenderId",
  appId: "웹 앱의 appId"
};
```

이 값은 브라우저에 제공하는 공개 설정입니다. 서비스 계정 JSON, private_key, 비밀번호는 필요하지 않습니다. 개인별 접근 제한은 3단계 보안 규칙이 담당합니다.

## 5. GitHub Pages 반영

`Calendar` 저장소의 배포 대상 브랜치에 다음 파일을 반영합니다.

- `pe/index.html`, `pe/sw.js`
- `pe/cloud.js`, `pe/cloud-sync.mjs`, `pe/firebase-config.js`

`firestore.rules`를 GitHub에 올리는 것만으로는 보안 규칙이 적용되지 않습니다. 반드시 3단계에서 Firebase에 게시해야 합니다.

## 6. 기존 일지 옮기기

1. 기존 일지가 있는 **기기와 브라우저**에서 사이트를 엽니다.
2. 우선 **설정 → 데이터 → 백업 파일 내보내기**로 기존 자료를 보관합니다.
3. 위쪽 **Google로 로그인**을 누릅니다.
4. **이 기기의 기존 일지 가져오기**를 누릅니다. 가져오기는 현재 계정의 일지를 교체하므로, 기존 계정 일지도 먼저 파일로 백업됩니다.
5. **온라인 저장 완료** 표시를 확인합니다.
6. 다른 기기에서 같은 계정으로 로그인해 시간표와 일지가 보이는지 확인합니다.

다른 선생님은 자신의 Google 계정으로 로그인합니다. 처음 로그인한 계정에는 빈 개인 일지가 열리며, 기기에 남아 있던 다른 사람의 일지가 자동으로 복사되지 않습니다. 기존 브라우저 일지는 가져오기 후에도 보존됩니다.

## 동작과 한계

- 로그인한 계정의 시간표, 일지, 수업 기록, 명렬표가 Firebase에 저장됩니다. 다른 선생님에게 공유되는 기능은 없습니다.
- 로그인하지 않은 일지는 기존처럼 브라우저에만 저장됩니다.
- 계정 일지를 불러온 뒤 인터넷이 끊기면 입력을 이 기기에 임시 보관하고 재연결 시 저장을 시도합니다. **처음 로그인하거나 새로고침한 직후 계정 일지를 불러오려면 인터넷이 필요합니다.**
- 서로 다른 기기에서 동시에 수정하면 덮어쓰기를 멈추고 백업과 온라인 일지 불러오기를 안내합니다. 자동 병합은 하지 않습니다.
- 기기 임시 저장 공간이 부족하면 화면에 실패를 표시합니다. 그 경우 창을 닫기 전에 파일로 백업합니다.
- 온라인 저장 완료 전에는 로그아웃을 막습니다. 브라우저를 닫아도 미전송 초안은 이 기기에 남으며, 같은 계정으로 다시 로그인하면 복구할 수 있습니다.
- 계정별 저장 단위는 일지 한 문서입니다. UTF-8 기준 750,000바이트가 넘으면 덮어쓰지 않고 백업·정리를 안내합니다.
- 로그인은 브라우저 세션 동안 유지합니다. 공용 PC에서는 사용 후 로그아웃합니다. 로그인 전 브라우저 일지와 미전송 초안은 해당 브라우저 저장소에 남습니다.
- 기본 제공 사용량을 넘으면 저장이 제한될 수 있습니다. Firebase 콘솔의 사용량 화면에서 확인합니다.

## 점검

개발 시 동기화 로직 테스트: `node --test pe/cloud-sync.test.mjs`

연결 후 실제 계정 A/B로 다음을 확인합니다.

1. A에서 기록을 저장하고 다른 기기의 A에서 같은 기록 확인.
2. B로 로그인하면 A의 기록이 보이지 않음.
3. Firestore Rules Playground에서 미인증 요청과 B가 A의 문서에 접근하는 요청이 거부됨.
4. 인터넷을 끊고 작성한 뒤 재연결하면 저장 완료 표시.
5. 두 기기에서 같은 일지를 수정하면 충돌 알림이 나오고 자동 덮어쓰기가 되지 않음.
